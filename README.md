# かたち

顔写真がなく、チャットもないマッチングアプリ。

見た目と会話の上手さを判断材料から外したときに、人は何で人を選ぶのか。
同じ問いへの答え、ハッシュタグ、診断の6軸だけで繋がる。

## 動かす

```bash
npm install
npm run dev      # http://localhost:3000
npm test         # ドメインロジックのテスト（34件）
npm run build
```

初回起動時に `.data/db.json` が作られ、13人分の初期データが入る。
作り直したいときは `.data/` を消せばいい。

デモでは `みずいろ` として振る舞う。認証はまだない。

## 触るところ

| 画面 | 中身 |
|---|---|
| `/` | 今日の問い。答えると、同じ問いに答えた人の言葉が読める |
| `/diagnostic` | 12問の診断。結果が「かたち」になる |
| `/tags` | ひとことタグ |
| `/discover` | 相性順の候補。出てくる理由が必ず添えられる |
| `/connections` | 相互成立した相手。お題を送る |
| `/exchange/[id]` | お題交換。二人とも答えると同時に開く |

`/discover` と `/exchange` には「（デモ）」と書かれたボタンがある。
相手の操作を手元で再現して、相互成立や交換の開封を試すためのもの。本番では消す。

## 構成

```
app/            画面（App Router）+ サーバーアクション
components/     Shape（診断結果から生成されるアイコン）
lib/
  types.ts      ドメインの型。画像を表す型は存在しない
  axes.ts       6軸の定義と12問の診断
  score.ts      相性の計算と、その理由の説明
  shape.ts      軸から図形を生成する
  questions.ts  日々の問い30問 / お題24問
  store.ts      開発用のファイルストア
  seed.ts       初期データ
supabase/       Postgres スキーマと RLS
docs/
  product.md          設計の考え方
  open-questions.md   決めていないこと
tests/          ドメインロジックのテスト
```

## この設計で外せないところ

- **写真を置く場所がない。** 型にもスキーマにもカラムがない。機能として付けないのではなく、置き場所を作らない
- **自由文のチャットがない。** テキストは必ず「特定の問いへの回答」としてしか存在できない
- **自分が答えるまで、相手の答えは読めない。** アプリの分岐だけでなく RLS でも縛っている
- **推薦の理由を必ず言う。** 説明できない推薦はしない

詳しくは `docs/product.md`。
