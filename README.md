# かたち

顔写真がなく、チャットもないマッチングアプリ。

見た目と会話の上手さを判断材料から外したときに、人は何で人を選ぶのか。
同じ問いへの答え、ハッシュタグ、診断の6軸だけで繋がる。

## 動かす

```bash
npm install
npm run dev      # http://localhost:3000
npm test         # ドメインロジックのテスト（79件）
npm run build

# パスキーの登録〜ログインを仮想認証器で通しで確認する
npm run build && npm run start
npm run e2e
```

初回起動時に `.data/db.json` が作られ、13人分の初期データが入る。
作り直したいときは `.data/` を消せばいい。

ログインは**パスキーのみ**でパスワードはない。初期データのユーザーには
パスキーが登録されていないので、開発時だけ `/signin` の下に出る
「パスキーなしで、みずいろとして入る」から入れる（本番では 404）。

## 触るところ

| 画面 | 中身 |
|---|---|
| `/signin` | パスキーの登録とログイン |
| `/` | 今日の問い。答えると、同じ問いに答えた人の言葉が読める |
| `/weekly` | **おまかせマッチ**。週にひとりだけ、システムが両者に同時に紹介する |
| `/diagnostic` | 12問の診断。結果が「かたち」になる |
| `/profile` | ひとこと・タグ・年齢・場所・性別と、相手に求める条件 |
| `/discover` | 相性順の候補。出てくる理由が必ず添えられる |
| `/connections` | 相互成立した相手。お題を送る。3回開くと**連絡先の受け渡し**が解放される |
| `/exchange/[id]` | お題交換。二人とも答えると同時に開く |

`/discover` と `/exchange` には「（デモ）」と書かれたボタンがある。
相手の操作を手元で再現して、相互成立や交換の開封を試すためのもの。本番では消す。

```

  ...           画面（App Router）+ サーバーアクション

  types.ts      ドメインの型。画像を表す型は存在しない
  axes.ts       6軸の定義と12問の診断
  score.ts      相性の計算と、その理由の説明
  shape.ts      軸から図形を生成する
  questions.ts  日々の問い30問 / お題24問
  weekly.ts     おまかせマッチのペアリングと状態
  handoff.ts    連絡先の受け渡し（アプリの出口）
  introductions.ts 週の紹介の生成と返事
  session.ts    署名付きクッキーのセッション
  viewer.ts     いま見ている本人（next/headers に触るのはここだけ）

  store.ts      開発用のファイルストア
```

## この設計で外せないところ

- **写真を置く場所がない。** 型にもスキーマにもカラムがない。機能として付けないのではなく、置き場所を作らない
- **自由文のチャットがない。** テキストは必ず「特定の問いへの回答」としてしか存在できない
- **自分が答えるまで、相手の答えは読めない。** アプリの分岐だけでなく RLS でも縛っている
- **推薦の理由を必ず言う。** 説明できない推薦はしない
- **断られたことが分からない。** おまかせマッチでどちらが見送っても、表示は同じ
- **入口に徹する。** 3回お題が開いたら連絡先を渡し合える。その先はアプリの外
- **条件は双方向でしか成立しない。** 片側だけ合っていても候補に出さない
- **パスワードを持たない。** パスキーのみ。預かるのは公開鍵だけ

詳しくは `docs/product.md`。

## いまの状態

パスキーでの登録・ログイン、診断、属性と条件、相性の提示、
つながりとお題交換、通報・ブロックまで動く。
データはローカルのファイル。Supabase のスキーマは書いてあるが、
クラウド側には何も作っていない。

判断待ちのことは `docs/open-questions.md` にまとめてある。
