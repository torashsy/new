## まだ決めていないこと

上から順に、進行を止めている度合いが高い。

### 1. パスキーと Supabase Auth の接続方法（技術的にいちばん大きい）

いま**アプリ自前のパスキー認証**を実装している。一方 `0001_init.sql` の RLS は
`auth.uid()` を前提に書いてある。このままでは Supabase に載せ替えたとき
`auth.uid()` が null になり、全ポリシーが落ちる。

| 案 | 中身 | 見立て |
|---|---|---|
| **A** | パスキー検証が通った時点で、Supabase の JWT シークレットで `sub = profiles.id` の JWT を自前で発行する | RLS をそのまま使える。いまのコードはこれを前提にしている |
| **B** | Supabase Auth 側のパスキー対応に寄せて、自前の `credentials` 表を捨てる | 自前で持つものが減る。Supabase の実装に縛られる |

**A で進めていいか確認したい。** B にするなら `lib/webauthn.ts` と
`app/api/auth/**` はほぼ捨てることになるので、早いほうがいい。

### 2. Supabase プロジェクトを作るか

スキーマ（`supabase/migrations/`）は3本書いたが、**クラウド側には何も作っていない**。
プロジェクト作成は課金に関わるので勝手にやらなかった。

いまはローカルのファイルストア（`.data/db.json`）で動いている。
切り替えは `lib/store.ts` の差し替えで済むようにしてある。

### 3. アプリ名

`かたち` は仮。パッケージ名は `katachi`。変えるなら早いほうがいい。

### 4. 「もっと知りたい」の上限は1日5人でいいか

数字は `lib/limits.ts` の `MAX_INTERESTS_PER_DAY` 一箇所で変えられる。
課金なしと決めたので、この上限を外す導線は作っていない。

### 5. 交換のあと、外部の連絡先に移る導線を作るか

いまは何度でもお題を交換できるだけで、終わりがない。
実際に会うところまで行くなら、どこかで外に出る必要がある。

beacon と同じく Capacitor で包むのか、Web だけで行くのか。

いま生年は自己申告で、18歳未満は保存できないようにしてあるだけ。
